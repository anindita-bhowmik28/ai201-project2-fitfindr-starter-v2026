# Acceptance criteria — FitFindr

Five criteria that say what "working" means for this agent, written in unit 3
**before** any results existed.

An acceptance criterion names a target: a number, a count, a rate, or something
a person could plainly observe. _"The agent handles errors"_ is an opinion.
_"When search returns nothing, the agent stops before calling the second tool,
in 5 of 5 tries"_ is a criterion.

Under each one, write a sentence or two on **why that target** and not a
stricter one. A reason that says something about your tools, your loop, or the
data earns credit; _"80% seemed reasonable"_ does not.

> Missing your own targets next unit costs you nothing. Setting a target so
> easy you can't miss it does.

**Two were provided, and three were added for this project.**

---

## 1. A matching query completes all three tools

Given a query that matches at least one listing, the agent completes all three
tool calls and returns a fit card — in at least 4 of 5 tries.

**Why this target:**
I chose 4 of 5 because the search depends on matching the user's words to the listing data, so different wording may occasionally fail to find an item even when a relevant listing exists.

---

## 2. An impossible query stops before the second tool

Given a query that matches no listings, the agent stops before calling
`suggest_outfit` and returns a message naming what to change — 5 of 5 tries.

**Why this target:**
I chose 5 of 5 because an empty search result is a clear condition that the planning loop can check directly. When the result is empty, the agent should consistently stop instead of sending a missing item to the next tool.

---

## 3. The selected item moves through session state correctly

For 5 matching queries, the item stored in `session["selected_item"]` has the same `id` as the item passed to `suggest_outfit` — in 5 of 5 tries.

**Why this target:**

I chose 5 of 5 because transferring the selected item through session state is deterministic and does not depend on model-generated wording. The item passed to the next tool should always be the same item that the agent selected from the search results.

---

## 4. The fit card identifies the selected item

For 5 successful queries, the fit card contains the selected item's title or a recognizable description of the selected item — in at least 4 of 5 tries.

**Why this target:**
I chose 4 of 5 because the fit card is generated by a model, so its wording can vary between runs. It does not need to repeat the exact title every time, but a useful caption should make it clear which selected item the outfit is built around.

---

## 5. Search results respect the user's price ceiling

For 5 queries that include a maximum price, every listing returned by `search_listings` has a price less than or equal to the requested maximum price — in 5 of 5 tries.

**Why this target:**
I chose 5 of 5 because the maximum price is a numeric filter handled by the search tool, not a subjective model-generated result. A listing above the user's stated budget should never be returned as a match.
